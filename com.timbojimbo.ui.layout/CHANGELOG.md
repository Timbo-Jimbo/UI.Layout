## [Unreleased]

### Added

- `LayoutNode`: one component per laid-out `RectTransform`, modelled on Clay's layout model. Per-axis `Sizing` (Fit, Grow, Fixed or Percent, with min and max), a layout `Direction`, `Padding` (one Vector4 in left, right, top, bottom order so bindings see four channels), `Gap`, child alignment on both axes, an `AspectRatio` that derives a Fit height from the width, and floating placement (`AttachTo` the parent, the root or another node, with an attach point on each side and an offset) that takes the node out of the flow and out of its parent's Fit size. A node whose parent object has no enabled node is a root; only roots are laid out, and everything below them is owned by the engine. Every field is a plain serialized value with a dirtying setter
- `LayoutEngine`: the algorithm as a pure pass over the tree. Content is measured unconstrained, Fit sizes accumulate bottom-up, each axis is sized top-down (Percent of the inner size minus gaps, Grow shares the remaining space smallest-first up to each max, on overflow Grow and Fit children shrink largest-first down to their minimum), content is measured again at its final width so text wraps before the vertical pass, then flow positions and alignment are resolved, and floating nodes are placed against their targets. Nothing touches a `RectTransform` until the commit, which writes anchors, size and position once and tracks them as driven properties, so a loaded scene starts with its nodes unsized and is laid out before its first render. Layout state is kept on the node (`LayoutRect`) rather than read back from the transform
- `LayoutNode.Offset`: a translation composed at commit that never affects siblings or the parent and never runs a pass; setting it moves the node in place, so it is the field to animate
- `LayoutTransition`: a delay, a duration and an `EaseType`, after CSS animation-delay, animation-duration and animation-timing-function. `LayoutNode.Transition` is the node's override inside a view transition, the way a CSS rule on `::view-transition-group(name)` overrides the default; outside one, layout is instant. `LayoutRect` is the target; `VisualRect` and `IsTransitioning` say where a node is on the way. Moves tick in the same pre-render hook as layout, after the dirty trees
- View transitions, after the web API. `LayoutSystem.StartViewTransition(update, transition)` captures where every enabled node is shown (in world space, so a node is matched across parents and trees), runs the update, lays the new state out, and animates the difference as one transition, returning a `ViewTransition` with `Finished` and `SkipTransition()`. The difference is sorted into groups the way the web sorts captured elements: movers (a node shown somewhere else travels there in place, from where it was; one that only rode its parent does nothing), named pairs, persisting pairs, exits and the topmost entering nodes. No snapshots are taken: the objects themselves move, so anything animating on them keeps going. Nodes move with the given transition (default `ViewTransition.DefaultTransition`, a quarter second easing out) unless they set their own; a transition with no duration applies the update at once. A layout pass during a transition leaves the moves alone, and a changed target retargets a moving node with the move's own timing. A root's own rect never animates, since it is what a ScrollRect or a UGUI parent reads. One transition runs at a time: starting another completes it (flights and moves land; enter and exit effects play on), `SkipTransition()` ends it effects included, and a duplicate name skips the transition with a warning, as on the web. Moves advance with the unscaled clock unless `LayoutSystem.UseScaledTime` is set, in which case they slow and pause with `Time.timeScale`
- The transition layer: named pairs and persisting pairs are lifted out of their trees into a plain rect kept as the last child of their canvas, a placeholder of the same size (and the same flow state) keeping each one's layout slot, and stacked there in capture order as the web's groups are in its top layer, so what draws over what no longer depends on the trees. Each flies a straight line from its captured rect to its slot, read live, so a scroll or a reflow during the transition is honoured; a lifted container keeps the layout its content was given for its final size. Enters and exits fade or play their animator in place beneath the layer (a leaving one lets clicks through). Nothing is left on an object afterwards but the fade's CanvasGroup
- `IViewTransitionAnimator`: how a node looks while it enters or leaves, the way keyframes on the web's old and new pseudo-elements do. The engine calls `Enter` on a node's first layout inside a transition and `Exit` when `LayoutSystem.Exit` takes it out, each with a `done` the transition's `Finished` waits for and that lets a leaving node go, and `Skip` when the transition is skipped. Only the topmost new node of a subtree enters, the rest rides with it. `ViewTransitionSequences`, present while the Sequencer package is installed (optional reference, `TJ_LAYOUT_SEQUENCER`), implements it with two authored sequences. Without an animator an entering or leaving subtree fades through a CanvasGroup, added the first time the object needs one and left in place; fades follow the move's own ease
- `LayoutSystem.Exit(node, onExited)`: takes a node out, the tree reflowing without it at its next pass while the node, still enabled, plays its exit effect (its animator's, or a fade with the running view transition's timing; outside one a node without an animator leaves at once); then the object is deactivated and the callback runs, so a page spawned for a transition can be destroyed on the way back. A delayed transition makes the siblings wait for the exit before closing up. `LayoutNode.IsExiting` says which state a node is in
- `LayoutNode.ViewTransitionName`, the web's `view-transition-name`, and `ViewTransitionScope`, which namespaces the names below a node (`scope/name`): part names are authored in a prefab and the scope is set to the item's id on the instance's root when it is bound, so a list of one prefab has no duplicates and a page given the same scope pairs with that instance's parts. A name found in only one state rides whatever its tree does
- `LayoutNode.ViewTransitionPersist`, after Astro's `transition:persist`: a pair with the flag is not cross-faded; the kept object flies into the new spot with its state intact, its content laid out against its rect as it goes, and when the transition ends the two swap places, the copy taking the old slot or going with the old tree if that tree is gone. A persisting object keeps its own sizing, so it is sized by a slot node on each side. A persisting background as an earlier sibling of a named body grounds a page transition: the surface itself grows from the card into the page while the bodies cross-fade over it
- `ILayoutMeasurable.SizeIsAnimatable` (default false): content that can be drawn between two sizes lets a transition animate the node's size; text keeps the position-only rule. UGUI content answers true for an Image, a RawImage or a bare LayoutElement and false for a graphic that measures itself (a text)
- `ILayoutMeasurable`: the leaf contract (`Measure(availableWidth)` and `MinWidth`), so content answers "how tall at this width" as a pure function
- UGUI compatibility inside `LayoutNode`: a leaf with no `ILayoutMeasurable` but with UGUI `ILayoutElement`s (LayoutElement, Image, TextMeshPro) measures them the way a UGUI group would, and every Graphic's dirty-layout callback marks the node, so a sprite or text change reflows the tree without any adapter component. This is a compromise kept in its own file: `ILayoutElement` only answers for the width on its transform, so the node writes the width it is asked about before reading (the pass then writes the real rect), and the minimum width is what the elements report, 0 for a text. Components that implement `ILayoutMeasurable` (TextBlock and Img do when this package is present) avoid both
- `LayoutRootBridge`: adapter for a root that sits inside a UGUI layout group or ScrollRect content. It reports the root's Fit size as an `ILayoutElement` (computed purely, no commit) and re-lays the tree out when UGUI resizes the root, so the content is right in the same frame. Each UGUI query is a full compute, so a bridged root costs three computes per UGUI rebuild
- `LayoutSystem`: `MarkDirty` and `ForceLayout`. Marked nodes are resolved to their roots and laid out on `Canvas.preWillRenderCanvases`, in both edit and play mode, ahead of UGUI's own rebuild so the graphics a commit resizes rebuild in the same frame. Roots are laid out outer first, and a pass that dirties a nested root (one under a plain rect it resized) is followed by that root's pass in the same flush. Static state is reset on every play mode transition with `[AutoStaticsCleanup]`, and the dirty set is keyed on managed reference identity, since an Undo resurrects a destroyed node with its old instance ID
- Property Bindings integration, present when `com.timbojimbo.propertybindings` is installed: `LayoutNodeProperties` descriptors (Offset, FloatOffset, Padding, Gap, AspectRatio, Width and Height values, Direction, AlignX, AlignY) and a `LayoutNodePropertyBinding` that writes through the setters, so the Sequencer and Styling drive a node exactly as code does. A Unity Animation clip, which writes fields directly, re-lays the tree out on its notification
- `Sizing` inspector drawer: the mode and only that mode's fields on one line
- Layout sample: a showcase scene with the sizing modes, alignment, shrink and wrap, floating, aspect ratio and a scrolling list, and buttons that add and remove rows, flip the sizing row's direction, change its gap and pulse a block's Offset
